# UE 5.8 Toon 金属材质渲染流水线架构解析

> 主角材质：`M_TV_ToonMetal_Master`
> 项目配置：**DX12、延迟渲染、Substrate、Lumen、虚拟阴影贴图**
> 引擎与源码版本：**UE 5.8.2**
> 说明：本文讲的是这套配置的**架构**，已核对配置与源码调用链，尚未抓取某个具体运行帧。

## 一帧总览

**金属材质节点与贴图 → 预先编译出各阶段使用的 Shader → CPU 更新场景与相机 → 筛选可见物体并组织绘制 → 准备深度、阴影和环境光照数据 → Base Pass 计算金属表面属性并写入 GBuffer → 灯光 Pass 计算直接光与 Toon 高光 → 统一处理 Toon 漫反射分档 → Lumen 提供间接光与环境反射 → 合成场景颜色 → 雾、透明物与后处理 → 抗锯齿、曝光和色调映射 → UI 合成 → 提交显示。**

---

## 术语速览

- **Shader，着色器**：在 GPU 上运行的小程序，负责变换顶点、计算像素，或者处理一批数据。
- **Pass，渲染阶段**：完成一个任务的一组 GPU 工作。例如"记录深度""计算灯光"。一个 Pass 可以包含很多次绘制。
- **Buffer，缓冲区**：保存中间结果的地方。可以把它理解为后面阶段要读取的工作表。

> **架构意识的核心是：每个阶段读什么、算什么、写什么，下一阶段为什么需要这个结果。**

## 1．材质准备：你搭建的是"表面属性的计算方法"

想象相机前有一块使用这套母材质的金属装甲，旁边有一盏灯，周围有墙壁和天空。

按照项目的[金属材质使用手册](D:/New_Bed_Wars-master/Documents/材质实例使用手册/M_TV_ToonMetal_美术使用手册.md)，材质主要整理这些信息：

| 输入 | 它回答的问题 |
|---|---|
| Base Color，底色 | 这块表面的基础颜色是什么？在金属区域，它还参与决定反射颜色 |
| Metallic，金属度 | 这里是金属，还是漆面、塑料等非金属？ |
| Roughness，粗糙度 | 反射是集中清晰，还是分散模糊？ |
| Normal，法线 | 这个位置的表面朝哪个方向？ |
| AO，环境光遮蔽 | 缝隙等位置需要怎样的间接光遮蔽？ |
| Anisotropy，各向异性 | 高光是否沿拉丝方向拉长？ |
| Toon Profile | 明暗、高光、阴影如何按艺术规则表现？ |
| Pattern UV | 图案与排线从什么坐标读取？ |

**法线贴图能让平面看起来凹凸，是因为它改变了光照计算时使用的朝向；模型轮廓仍由几何形状决定。**

你的材质还有一条金属球染色路径：

```text
表面法线转到相机坐标系
→ 用朝向生成贴图坐标
→ 读取 MetalSphereTexture
→ 在暗部色、亮部色之间混合
→ 修改最终 Base Color
```

所以转动相机时，染色区域也会移动。**这条路径在表面属性计算时发生，后面仍会计算真实灯光高光和环境反射。**

母材质默认的球染色强度是 0，各向异性也是关闭状态；默认 ORM 为白色，对应金属度 1、粗糙度 1、AO 1。理解架构时，可以想象一个把粗糙度调到 0.25 的实例，方便看到集中高光与反射。

## 2．编译：材质图怎样变成 GPU 能执行的程序？

编译发生在编辑、构建或需要新版本 Shader 时。正常绘制每帧使用已经准备好的程序。

```text
材质节点
→ UE 生成 HLSL 代码
→ 与 Base Pass、深度等阶段的 Shader 模板组合
→ DXC 编译器生成 DXIL
→ 驱动为当前 GPU 准备机器指令
→ 运行时绑定并执行
```

解释一下中间两个名字：

- **HLSL**：写 Shader 的语言。材质图中的采样、乘法、混合，最终会表达成代码。
- **DXIL**：DirectX 使用的中间程序格式，驱动再将它转换为适合具体 GPU 的执行形式。[微软编译器说明](https://github.com/Microsoft/DirectXShaderCompiler/blob/main/docs/DXIL.rst)

一个材质会参与多个阶段，因此通常需要多个 Shader 版本。例如深度阶段主要关心位置，Base Pass 要计算表面属性。

直接灯光阶段则可以读取已经保存的属性，使用引擎的公共光照 Shader。

你还能遇到 **PSO，流水线状态对象**：它把使用哪些 Shader、怎样比较深度、怎样混合颜色等配置组合起来，供 GPU 绘制时使用。

源码上，Toon 节点的生成入口在：

[MaterialExpressionSubstrate.cpp](D:/UE5.8.2src/Engine/Source/Runtime/Engine/Private/Materials/MaterialExpressionSubstrate.cpp:2489)，之后由材质翻译器生成相应代码。

## 3．CPU 准备一帧：决定要画什么、怎样组织工作

一帧开始，CPU 已经知道：

- 装甲的位置和姿态；
- 相机的位置和朝向；
- 灯光的位置、颜色、强度；
- 材质实例当前使用的参数和贴图。

这些信息进入渲染侧，组织成 GPU 能读取的数据和命令。

可以这样理解几个层次：

```text
游戏线程：更新世界
→ 渲染线程：根据相机组织渲染工作
→ RHI：把 UE 的命令转成 DX12 等图形接口命令
→ GPU：执行这些命令
```

**RHI 是 UE 对不同图形接口提供的统一接口。** 它让上层渲染代码不必为 DX12、Vulkan 分别重写全部逻辑。

这些层次可以重叠工作：CPU 准备后续帧时，GPU 可能还在执行前面的帧。

UE 用 **RDG，渲染依赖图**，记录各 Pass 需要读取和写入的资源，再安排执行、资源转换与同步。例如灯光必须等表面属性写好才能读取。[Epic RDG 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/render-dependency-graph-in-unreal-engine)

整帧的主要源码入口是：

[FDeferredShadingSceneRenderer::Render](D:/UE5.8.2src/Engine/Source/Runtime/Renderer/Private/DeferredShadingRenderer.cpp:1822)。

> **以后看 Renderer 源码，先在这里找阶段，再进入目标阶段的实现。**

## 4．可见性与深度：先解决"屏幕上是谁"

相机看不到的物体，通常不需要参与主画面绘制。

UE 会筛选相机范围内的物体、选择合适的细节级别，并利用遮挡信息减少工作。例如装甲完全藏在墙后时，可以避免部分后续绘制。

接着，**PrePass，深度预处理阶段**，先记录可见表面离相机多远。

它的产物是 **SceneDepth，场景深度图**：

> 屏幕上每个位置，前方表面对应什么深度？

后面画金属时，GPU 可以比较深度，尽早跳过被挡住的表面，减少昂贵的材质计算。

深度还会生成 **HZB，分层深度图**：把深度整理成逐级缩小的图像，方便快速判断较大区域是否被挡住，也供一些追踪算法使用。

同一帧还需要 **Velocity，运动向量**，记录表面在屏幕上从哪里移动到哪里。后面的时间抗锯齿会用它对齐前一帧。

若模型启用了 Nanite，几何筛选与光栅化会经过专门路径。这里先记住它接入的是"确定可见几何与表面"的部分。

## 5．阴影与环境准备：为后面的光照提供查询依据

从相机看见某个位置，不代表灯光也能照到它。

阴影系统需要回答：

> 从灯光到这个金属表面的途中，有没有东西挡住？

项目使用 **VSM，虚拟阴影贴图**。它将阴影数据拆成页面，按需要更新，并复用有效缓存。之后计算灯光时，查询这些数据来确定遮挡程度。[Epic VSM 文档](https://dev.epicgames.com/documentation/unreal-engine/virtual-shadow-maps-in-unreal-engine)

Lumen 也需要维护用于查询的场景与光照数据，供后面的间接光和反射使用。

因此，总流水线在这里开始出现分支：

```text
相机观察场景 → 深度与表面数据 ─┐
灯光观察场景 → 阴影数据 ─────┼→ 后续光照
Lumen 维护场景与光照数据 ────┘
```

**开头的箭头表达依赖主干。实际一帧是多条支线汇合的图，一些工作可以并行，一些数据可以跨帧复用。**

## 6．Base Pass：把金属表面填写进 GBuffer

这是材质图与整帧架构连接最直接的地方。

传统网格绘制可以先按这条链理解：

```text
读取模型顶点
→ 顶点 Shader 把模型投影到屏幕
→ 光栅化确定三角形覆盖哪些像素位置
→ 像素 Shader 计算这些位置的材质属性
→ 写入 GBuffer
```

**光栅化**就是把三角形变成屏幕上的覆盖区域。GPU 在区域内插值得到 UV、法线等信息，再计算材质。

你的金属材质此时主要做：

```text
读取底色、ORM、法线等贴图
→ 计算金属度、粗糙度与最终法线
→ 计算金属球染色、拉丝参数与图案坐标
→ 构造 Toon 表面数据
→ 保存结果
```

**GBuffer，几何缓冲，是几张按屏幕位置排列的表面信息图。**

想象屏幕中央有一个位置落在装甲上，GBuffer 为它记录：

> 底色是多少、金属度是多少、粗糙度是多少、表面朝向哪里、采用什么着色方式。

你项目选择了 **Substrate Blendable GBuffer**，即把 Substrate 表面整理到可混合的 GBuffer 表示中。Toon 的 Profile ID 和 Pattern UV 会打包到其中的 CustomData，供后面恢复。

源码可从这两处追：

- [BasePassPixelShader.usf](D:/UE5.8.2src/Engine/Shaders/Private/BasePassPixelShader.usf:910)：计算材质并组织输出。
- [SubstrateExport.ush](D:/UE5.8.2src/Engine/Shaders/Private/Substrate/SubstrateExport.ush:1281)：把 Toon 数据写入 GBuffer。

> **材质图此时交出了表面信息，灯光阶段接着读取它。** 这正是"延迟渲染"的主要组织方式。

## 7．直接灯光：把表面属性变成灯光贡献

灯光 Pass 读取：

```text
GBuffer 的表面属性
＋ 深度所确定的位置
＋ 灯光参数
＋ 阴影数据
＋ Toon Profile
→ 当前灯光对这个位置贡献多少颜色
```

它主要处理两类响应：

- **漫反射**：光进入表面附近后散开，外观通常比较柔和。
- **镜面反射**：光沿与表面朝向相关的方向反射，包括灯光产生的高光。

金属最重要的区别，可以直接从本机源码里的公式理解：

```text
漫反射颜色 = BaseColor × (1 − Metallic)

F0 = 在"非金属反射率"和 BaseColor 之间，按 Metallic 混合
```

**F0 是正面观察时的镜面反射率参数**，描述反射光的比例与颜色。

例如金属度为 1、底色为 `(0.8, 0.6, 0.2)`：

- 上述漫反射颜色变成 0；
- F0 取这个带颜色的底色；
- 外观主要通过镜面反射路径体现，包括灯光高光与环境反射。

你的 Toon 高光还会经过 Profile 控制的 **Ramp**。Ramp 可以理解为一条查找曲线：输入连续变化的高光响应，输出美术设定的颜色或档位。拉丝参数则改变高光沿不同方向的分布。

对应实现是：

[SubstrateToonEvaluateCommon](D:/UE5.8.2src/Engine/Shaders/Private/Substrate/SubstrateToonBSDF.ush:67)。

> 这套实现有自己的高光分档规则；研究时应沿这个函数看实际计算。

## 8．统一 Toon 漫反射：这套项目多出的一个接点

项目开启了 `ToonUnifiedDiffuse`，源码中存在单独的：

其思路是：

```text

→ 得到统一的明暗输入
→ 查询 Toon Profile 的漫反射 Ramp
→ 将结果加到场景颜色
```

这让多灯情况下的明暗分档有一个统一处理位置。

源码中的入口是：

[LightRendering.cpp](D:/UE5.8.2src/Engine/Source/Runtime/Renderer/Private/LightRendering.cpp:2506)。

但要结合上一节理解：**完全金属区域的基础漫反射颜色为 0**，这条路径更容易在部分金属、漆面或其他非金属区域体现；金属主体仍重点看高光与环境反射。

## 9．Lumen：给金属提供周围世界的光与倒影

前面的灯光回答"这盏灯怎样照它"。Lumen 进一步处理：

- **间接光**：光先照到墙壁等物体，再影响其他表面。
- **环境反射**：金属朝这个方向反射时，周围有什么可见内容？

对金属而言，环境反射非常重要：墙壁、天空和场景结构，会形成它表面的大块颜色与形状。

Lumen 反射可以按下面的流程理解：

```text
读取深度、法线、粗糙度等信息
→ 确定反射方向
→ 先尝试查询屏幕中的场景
→ 根据配置使用其他场景追踪补充
→ 过滤噪声并结合历史结果
→ 按金属的反射响应合成到场景颜色
```

**屏幕追踪**利用当前画面已有的深度与颜色来找反射内容；其他追踪方式补充屏幕信息不足的部分。Lumen 支持软件和硬件追踪路径。[Epic Lumen 技术说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-technical-details-in-unreal-engine)

粗糙度还可能改变这里的计算路径：较光滑的像素会追踪专门的反射射线，较粗糙的像素可以使用粗糙反射近似。因此，粗糙度调整可能同时改变画面与反射成本。[Epic Lumen 性能说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/lumen-performance-guide-for-unreal-engine)

你项目的 Toon Profile 还参与间接光强度控制，开启的反射量化选项会在相关合成路径中对间接反射进行分档处理。

反射入口：

[RenderLumenReflections](D:/UE5.8.2src/Engine/Source/Runtime/Renderer/Private/Lumen/LumenReflections.cpp:1215)。

## 10．场景合成、后处理与显示：把光照结果变成最终画面

直接光、间接光、反射等贡献逐步合成到 **SceneColor，场景颜色图**。

SceneColor 保存的亮度可以超过 1，这就是 **HDR，高动态范围**：很亮的灯光和高光暂时不必挤进显示器可表达的范围。

后面继续处理：

- 雾、天空、大气和透明物，影响金属最终被看见的颜色；
- 时间抗锯齿或 TSR，结合历史帧、深度和运动信息减少闪烁；
- Bloom，让很亮的区域产生辉光；
- 曝光，调整画面整体亮度；
- 色调映射，把较宽的亮度范围映射到显示输出；
- UI 与编辑器界面等合成，最后提交显示。

这些处理在实际配置中有各自的执行位置。例如时间重建通常处理仍处于 HDR 的场景颜色，透明内容也可能分阶段合成。

后处理入口是：

[AddPostProcessingPasses](D:/UE5.8.2src/Engine/Source/Runtime/Renderer/Private/PostProcess/PostProcessing.cpp:412)。

> **观察金属高光时，要同时看光照结果和后处理：最终屏幕上的亮度、颜色、边缘形状，都可能继续被改变。**

## 11．把架构再放大一层：一个 Shader 在 GPU 内怎样执行？

选 Base Pass 中的一个像素计算：

```text
拿到插值后的 UV、法线
→ 发出纹理读取请求
→ 将返回数据保存在寄存器
→ 执行乘法、混合、坐标变换
→ 输出 GBuffer
```

GPU 会把大量 Shader 工作分组执行。这样的执行组常叫 **Wave**；NVIDIA 常用 **Warp** 这个名字。

这里就接上你要学习的性能链路：

| 概念 | 小白理解 | 在金属材质中的对应 |
|---|---|---|
| 纹理读取 | 程序向存储系统取数据，需要时间 | 底色、法线、ORM、球面图、Profile 查找 |
| 缓存 | 保存近期可能重复使用的数据，减少下层存储访问 | 相邻像素读取相近贴图区域时，有机会复用数据 |
| 寄存器 | 保存当前正在计算的临时值 | 法线、颜色、坐标、拉丝方向等中间结果 |
| 并行度 | 同时有多少工作可以驻留和推进 | 一组工作等待数据时，调度其他就绪工作 |
| 带宽 | 单位时间能搬运多少数据 | 贴图读取、GBuffer 写入和后续读取 |

它们是相互影响的：

> 中间值同时存活得越多，可能需要越多寄存器；寄存器资源有限，可能减少同时驻留的工作组；如果就绪工作不足，纹理等待就更难被其他计算掩盖。

寄存器压力很高时，还可能把临时数据放到内存，引入额外访问。具体是否发生，要看编译结果与硬件指标。[NVIDIA Shader 性能说明](https://developer.nvidia.com/blog/advanced-api-performance-shaders/)

因此，**"贴图多""指令多""并行度低"分别是线索，耗时及硬件指标才帮助你判断它们有没有成为瓶颈。**
